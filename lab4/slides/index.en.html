Our focus: the ID3 index fingertip sensor

Why focus on ID3?

A smaller experiment makes the learning problem easier to understand.

Fixed hand pose, recorded motion, one sensor target. Motion remains part of the input.

What changes during a touch?

Approach, press, release. The sensor responds over time.

Conceptual animation. Material, friction and loading history also affect the signal.

One touch, three signals

Each ID3 packet contains three force components.

Measured episode 5. Nominal SDK N; the SDK axes are not assumed to be surface-normal coordinates.

Replay produces paired observations

The same recorded event has a simulation description and a sensor response.

Pairing means time correspondence. Geometry and measured force can have different units and errors.

The data you will use

The lab begins with a supplied dataset; no new collection is required.

Synthetic variants are labelled separately. They are not 300 independent hardware trials.

A short history adds context

The same position can occur while loading or while releasing.

Only current and past frames are used. Seven frames × eleven features = 77 input values.

Where does an MLP fit?

MLP means multilayer perceptron: a basic feed-forward neural network.

Mean prediction and linear regression are simpler baselines. An MLP is a model family, not a data format.

One neuron: mix, then transform

Weights set the contribution of each input. A bias shifts the response.

Toy standardized inputs and example weights. The lab uses tanh activations in its hidden layers.

Layers build a prediction

Many neurons create intermediate features; the final layer predicts force.

Default architecture: 77 → 48 → 48 → 3. Hidden activations: tanh. Output: linear, for signed force.

Training means reducing prediction error

Use paired examples to adjust the weights, then check a separate validation set.

The code uses MSE on standardized targets and Adam. Report force errors after reversing the scaling.

A prediction becomes more useful

Compare the predicted curve with the measured target.

Illustrative interpolation, not epoch logs. The endpoint is the actual MLP prediction on held-out episode 5.

Why introduce a latent space?

We want a reusable description of a touch, as well as a force prediction.

Latent means hidden: a code inferred from data. Here we train a small bottleneck to preserve input information.

A curve can have a compact description

Many sample values can change together.

Toy curve with hand-chosen parameters. Learned latent coordinates do not automatically mean amplitude or width.

An autoencoder learns to reconstruct

Encoder: make a code. Decoder: use the code to rebuild the input.

Sensor history: 7 × 3 = 21 values. A four-value latent code must support reconstruction of all 21.

The bottleneck is a design choice

A shorter code encourages compression, but may lose useful detail.

Small does not guarantee meaningful, noise-free or disentangled. Judge reconstruction on held-out data.

What does a latent space look like?

A code is a point in a learned coordinate space. Each dot is one sensor history.

Actual four-dimensional sensor codes, shown with PCA fitted on training data. Axes have no preset physical meaning.

Two encoders, two coordinate systems

Similar events need not receive the same numerical code.

Latent axes can change scale, order or orientation. Pairing supplies examples of the correspondence.

First, teach each side to reconstruct

Learn each representation before learning how to translate between them.

Each encoder and decoder is an MLP. Use the training split, with validation for checkpoint selection.

Then learn the latent translation

Freeze the endpoints and train the mapping T on paired examples.

Decoder output: 21 values. We take its last three values as the current force prediction.

Where can reconstruction go wrong?

Separating the stages helps us diagnose a bad prediction.

Good self-reconstruction does not guarantee good sim2real prediction. Some signal factors may be missing from the input.

Evaluation follows original episodes

Keep related windows and synthetic variants in the same split.

Fit standardization on training data. Choose settings on validation. Reserve the test episode for final reporting.

More structure does not guarantee lower error

Compare both approaches on the same measured test episode.

Three-axis RMSE in nominal SDK N, episode 5. This comparison uses the default seven-frame window and fixed seed.
